# CainOS

CainOS is a retro C&A mainframe-style interactive web app inspired by The Amazing Digital Circus.

## Digital Circus — Encore

CainOS includes **Circus Combat — Encore**, a shared combat application and
standalone game adapted from the real CQC engine of `shadow-codec-ops`.
The playable game version is **0.7.0**. The GLITCH wardrobe was updated on **18 November 2026**; the latest Circus appearance continuation is dated **20 November 2026**.

- In CainOS: complete the existing first-use calibration, then launch **Circus Combat**.
- Direct game: open **`/combat/`** on the same static server.
- Independent distribution: run **`npm run build:combat`**, then serve **`dist-combat/`**.
- Production tracker: **[DIGITAL_CIRCUS_COMBAT_TRACKER.xlsx](docs/DIGITAL_CIRCUS_COMBAT_TRACKER.xlsx)**.
- Controls, architecture, references and remaining work: **[Digital Circus — Encore](docs/DIGITAL_CIRCUS_ENCORE.md)**.
- To equip a crossover, open the fighter or opponent’s wardrobe and select **Filtrer les tenues**. Choose the series and **Fusion originale** to see the character’s redesigned body. [Compare the fusion portraits and combat stances](docs/COMBAT_GALERIE_FUSIONS.md) or [browse the GLITCH wardrobe and arena gallery](docs/COMBAT_CROSSOVERS_GLITCH.md).

The game combines **54 fighters, 540 techniques, 22 shared arenas, 462 selectable costumes and 179 searchable archive entries**. Fourteen fighters have individually authored kits; 40 promoted archive NPCs use the extension kits described below. The 54 dedicated stage arrangements reuse shared scenery and are counted separately. Its nine standard modes are joined by nine illustrated crossover visits under **Escales GLITCH**. The wardrobe contains 51 archive costumes, 33 additional illustrated Circus appearances, 252 tributes and residents, and 126 original fusions for the original fourteen fighters. Crossovers for the forty promoted NPCs remain to be produced. The combat techniques and stories are original fan-game adaptations.

### Rival, coupe et feuille de route — historique de l’extension à 14 artistes

**La coupe du cirque** garde son tableau à huit participants et ses trois duels
joués, mais chaque artiste a désormais un **rival attitré**, tiré de sa propre
route narrative. Le rival est placé dans l’autre moitié du tableau : ses
rencontres CPU sont résolues par le scénario, restent étiquetées comme simulations
et il attend en finale. Une défaite du joueur offre la coupe au rival. Une intro
authored (Caine, le rival, l’artiste) précède le premier duel et un couronnement
propre à l’artiste conclut la victoire. Le prix est toujours un rôle dans le
spectacle — jamais une sortie du cirque.

Les quatorze histoires exposent maintenant leur **feuille de route** : intro,
nombre d’adversaires à battre (quatre), chapitre du rival, épilogue verrouillé ou
débloqué. Le bouton **La feuille de route** affiche les quatre chapitres avec leur
adversaire, leur arène et le marqueur ◆ du rival. Aucun nouveau chapitre ni combat
n’est ajouté : ces données sont dérivées des routes existantes.

Les **87 illustrations** de cette extension sont décrites, pas produites : trois
images génériques de coupe, quatorze entrées, quatorze face-à-face de rival,
quatorze couronnements et quarante-deux tableaux d’histoire. Voir le
[brief d’illustrations](docs/COMBAT_TOURNOI_HISTOIRES_ILLUSTRATIONS.md). Les règles
de simulation, les replays, les profils et la version du jeu restent inchangés.

multi-match programmes save the start of the current encounter. Reloading keeps
earlier victories, rather than a simulation frame in the middle of a duel.

### Offline installation

On HTTPS or localhost, choose **Réglages → Télécharger le spectacle** and wait for
the complete illustration count shown by the game. The current file list, byte
count, artwork identity and code build identity are generated in
[offline-manifest.mjs](combat/offline-manifest.mjs). The former 44-sheet pack belongs
to the original October 0.7 release. Use the installed shortcut or
`/combat/index.html?standalone=1` for later offline visits.

Updates are explicitly offered in settings. Unchanged illustrations survive a
code-only update; changed art requires preparing the new pack. Failed or timed-out
installation offers a retry. Clearing illustrations preserves the profile and
controls. The worker covers the combat path, not the CainOS desktop or the
standalone root redirect. Static builds require HTTP; opening files directly with
`file://` is unsupported. Native application packages remain separate work.

## Profile recovery and distinct confirmations — 29 October 2026

This guided follow-up applies `save-systems` and `audio-design` to the shared game.
The first successful profile save and later saves attempt to keep a complete
backup, after the primary write. A present but unreadable primary can recover
from that valid copy without rewriting storage during load. A persistent notice
on Home and Settings offers export or explicit repair; it explains that the copy
may be older. A deleted primary stays deleted, and corrupted cross-tab data cannot
erase an already valid in-memory profile or replace it with an older backup.

its newer progress. Rejected storage writes retain export

## Development and build

```bash
python3 -m pip install -r scripts/requirements-gamedev.txt
npm ci
npm run dev
npm run build
npm run build:combat
npm run qa
```

The default build includes CainOS, the combat app and the existing cloud-account
runtime. The separate combat build needs no OS runtime. `npm run qa` runs the
CainOS audits, behavioral tests, syntax checks, manifest generation and both builds.
It also runs the selected-guide and asset audits. These development checks use
Python 3.12 and Pillow as pinned in `scripts/requirements-gamedev.txt`; Python
and Pillow are not part of the browser game.
